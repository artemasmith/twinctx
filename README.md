# TwinCtx

TwinCtx собирает для ИИ-агента выдержки из заметок, кода и памяти. На выходе — текст в заданном бюджете и манифест с источниками. Если релевантных фрагментов нет, агент получает пустую подборку. Базовый режим работает локально на SQLite FTS5, без ключей API и скачивания моделей.

## Попробовать на одной заметке

Для примера нужны Python 3.11+ с SQLite FTS5 и терминал macOS или Linux.

```sh
git clone https://github.com/artemasmith/twinctx.git
cd twinctx
python3 -m venv .venv
. .venv/bin/activate
python -m pip install .

export HARNESS_HOME="$(mktemp -d)"
export VAULT_DIR="$HARNESS_HOME/vault"
export TWINCTX_STORE=sqlite TWINCTX_EMBED=none
mkdir -p "$VAULT_DIR"
printf '%s\n' '# Архив' 'Резервные копии хранятся 45 дней.' > "$VAULT_DIR/archive.md"

twinctx index
twinctx query 'Сколько дней хранятся резервные копии?' --json
```

В поле `packed` появится текст про 45 дней, а в `manifest.items` — источник `vault/archive.md`. Для постоянной работы укажите в `HARNESS_HOME` каталог для индекса и памяти, а в `VAULT_DIR` — каталог ваших Markdown-файлов.

## Подключить агента

Установите MCP-адаптер в том же окружении и запустите его через MCP-клиент по stdio. В конфигурации клиента укажите полный путь к исполняемому файлу `.venv/bin/twinctx-mcp` и передайте те же значения `HARNESS_HOME`, `VAULT_DIR`, `TWINCTX_STORE` и `TWINCTX_EMBED`.

```sh
python -m pip install '.[mcp]'
```

Агент может запросить контекст через `context_assemble`, прочитать конкретный источник через `context_read` и записать факт через `context_remember`. Из терминала память доступна через `twinctx remember`. Поиск поддерживает переходы по ссылкам между заметками и ограничение выборки по корпусу. Опциональные адаптеры устанавливаются отдельно через extras `embeddings`, `postgres` и `privacy`.

Индексатор также читает задачи из `$HARNESS_HOME/workspace/<проект>/.tasks/*.yaml` и журнал из `$HARNESS_HOME/journal/`. Интеграция с Hermes в этой поставке доступна через MCP.
